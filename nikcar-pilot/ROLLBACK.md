## Проверки перед публикацией
1. Запустить `node --test nikcar-pilot/tests/smoke.test.cjs`; все тесты должны пройти.
2. Проверить GitHub Actions и убедиться, что используется ожидаемый commit SHA.
3. Проверить вход владельца, бухгалтера и водителя, просмотр документов, сохранение автомобиля, расчёт аренды, бесплатные выходные без списания старого долга. **Не тестировать запись на реальных данных:** использовать тестовый стенд/аккаунты.
4. После публикации проверить `/index.html`, `/app.js`, `/style.css`, `/modules/diagnostics.js`, `/modules/upload-retry.js` (HTTP 200), затем интерфейс iPhone и Android.
5. В случае ошибки остановить дальнейшие изменения и выполнить откат кода.

## Откат без переписывания истории
1. Сначала зафиксировать текущий commit SHA, Render deploy ID и симптомы.
2. В GitHub создать отдельную ветку от последнего `main` и revert проблемных коммитов через PR. Для экстренного восстановления можно восстановить файлы из `backup/pre-6.4-2026-11-16` в новом коммите (без force push).
3. Дождаться автоматического деплоя Render из `main`. Альтернатива: вручную повторно развернуть **конкретный предыдущий успешный деплой** через панель Render, если эта операция поддерживается текущей конфигурацией. Учесть: следующий push в `main` снова изменит live.
4. Проверить доступность сайта, авторизацию, документы и финансовые операции. При проблемах с кэшем PWA проверить загрузку новой версии на устройстве.
5. Отдельно проверить совместимость кода и схемы Supabase: откат кода **не откатывает** миграции БД.

## Важные ограничения
- Не удалять записи Supabase и не восстанавливать всю БД ради отката интерфейса.
- Миграции БД выпускать отдельно, сначала добавляя совместимые функции/поля. Удаление старых функций — только после подтверждения стабильности.
- Не использовать `git reset --hard` + force push на основной ветке.
- Автоматические smoke-тесты не заменяют E2E, проверку прав доступа и проверку на физических устройствах.
